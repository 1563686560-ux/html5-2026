# 知识库真实问答验收

日期：2026-09-20。模型：项目现有 DeepSeek 接口的 `deepseek-chat`。

## 结论

本次使用两份人工编写的虚构中文资料进行九道单轮问题验收。首次运行有八道通过，一道无关问题因问句中的“期是”误命中资料。修复问句套语和通用谓语的权重后，以同一批问题重新运行：九道规则检查全部通过。人工逐条核对后，八道实际模型回答的事实和引用均与对应资料一致，中文通顺，未观察到两份资料的事实串用；无关问题在检索阶段返回空结果，没有调用模型。

这说明本次已知误召回得到修复，但仍不能据此保证所有真实文档都能可靠问答。复杂 PDF、向量检索、多轮追问和长文档仍未覆盖。

## 范围与方法

- 使用 `tests/fixtures/rag/星桥项目.txt` 和 `海岚项目.txt`，项目名称、日期、金额均为虚构设定。
- 两份资料故意使用不同的前端框架、存储位置、活动安排与金额，用于检查事实串用。
- 调用项目原有的分块、RAG store 关键词检索、引用合并、提示词组装与流式客户端；关闭 Embedding，不读取用户知识库。
- 每题仅运行一次；生成温度与应用一致，命中资料时为 0.3。
- 命中为空的指定资料问题采用与应用一致的固定提示；这部分由验收脚本执行，没有经过浏览器聊天状态机。
- 自动检查关键词、禁止出现的另一份资料事实、来源范围、引用编号与流结束标志；再人工核对语义和引用内容。
- 不覆盖浏览器导入、PDF 解析、向量检索、多轮追问、长文档、移动端和重复运行稳定性。

## 逐题结果

| 测试 | 预期重点 | 实际结果 |
| --- | --- | --- |
| 星桥技术 | Vue 3、Vite、本机 IndexedDB | 正确，引用支持结论 |
| 海岚技术 | React、Webpack、服务器 PostgreSQL | 正确，没有混入星桥方案 |
| 星桥报名 | 10月28日截止、3至5人、不收费 | 三项均正确 |
| 星桥经费 | 1200元、证书、不发现金 | 正确 |
| 海岚经费 | 3600元、每获奖团队300元及证书 | 正确 |
| 未提供的信息 | 不编造评委姓名和电话号码 | 明确说明资料未提供 |
| 无关天文问题 | 不召回资料，不调用模型 | 修复后通过：检索为空，直接提示所选资料没有相关内容，没有调用模型 |
| 连贯解释 | 解释离线限制和引用核对方法 | 中文连贯，两项均有资料依据 |
| 全部资料对比 | 正确区分两项目事实与引用 | 正确；海岚对应[1]，星桥对应[2] |

首次运行中，无关题错误召回了资料并调用模型。原因是“周期是多少”与“截止日期是”共享二元片段“期是”，旧检索把它当成强相关证据。修复后，检索会先切掉“多少、什么、如何”等问句套语，并降低“运行、使用、进行”等通用谓语在长问句中的权重；用户直接搜索这些词时仍可命中。修复前的原始结果保存在 `知识库真实问答-修复前.json`。

## 代表性实际回答

技术题：

> 星桥项目的展示网站使用 Vue 3 构建界面，使用 Vite 打包，资料和浏览记录存储在本机的 IndexedDB 中，不上传到项目自己的服务器 [1]。

资料不足题：

> 资料中没有提供评委姓名和联系电话，也明确说明不能根据负责人姓名推测联系电话 [1]。

无关题（修复后由应用固定提示，不调用模型）：

> 在所选资料中没有检索到足够相关的内容。请换一种问法，或检查是否选对了资料。
