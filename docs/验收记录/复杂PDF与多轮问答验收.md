# 复杂 PDF 与多轮问答验收

验收日期：2026-09-20

## 覆盖范围

- 浏览器实际选择并解析 3 页 PDF，再点击“导入资料”保存。
- 表格字段问答：可用时段、每队上限、押金、负责人。
- 跨页规则问答：归还条件从第 2 页延续到第 3 页。
- 连续追问：先问云镜展示屏，再追问“什么时候退回？”。
- 资料不足：电话号码和停车费用均不得推测。
- 引用编号：答案引用必须指向本轮所选资料中的有效原文。

## 结果

浏览器导入成功。应用识别出 3 页正文，保存为 1 份资料、3 个片段；表格内容、跨页结论以及“未提供的信息”均保留。

真实模型使用 `deepseek-chat`，4 项问答全部通过：

| 场景 | 结果 | 关键检查 |
| --- | --- | --- |
| 表格 | 通过 | 全天、60 分钟、500 元、顾言 |
| 连续追问 | 通过 | 检索查询补入上一问中的“云镜展示屏”，回答包含完整退款条件 |
| 跨页 | 通过 | 明确仅关闭屏幕不够，并列出关机、断电、线缆归位、负责人验收 |
| 资料不足 | 通过 | 明确资料没有提供电话号码和停车费用，没有编造 |

原始模型输出和引用快照见 `复杂PDF真实问答.json`。

## 验收中修复的问题

原实现只用当前一句检索，省略对象的追问容易丢失上一问主题。现仅对短、省略主语的追问补入上一条用户问题，并保持用户原话和对话历史不变。

第一次规则复核还发现，带明确主题的“多少”问题可能被误认成追问。判定已收紧：通用追问词前存在明确主题时不再拼接旧问题，并已添加回归测试。
