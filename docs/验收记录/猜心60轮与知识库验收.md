# 猜心 60 轮与知识库验收

日期：2026-10-08。此记录接续《猜心底层完善》，对应用户后续确认的知识库接入方案。

## 已实现

- 游戏、界面说明、提示词和真实测试共用 `MAX_ROUNDS = 60`。第 60 轮仍未猜中时如实结束，不生成第 61 轮。每轮生成与核对仍共享 30 秒等待上限。
- 将奶龙参考资料一次性导入现有「问知」知识库，和用户导入资料采用同一文档及分块存储。包含来源链接，可查看、删除；导入标记与资料在同一事务中写入，避免重复导入，删除后不会自动补回。
- 猜心按已回答的肯定问句提取检索词，过滤问句套语。程序检索资料，大模型决定提问和猜测，不在本地按属性直接决定答案。
- 资料以外部参考形式单独传递，不并入用户事实清单，不执行资料里的指令。候选核查只检索候选名称，避免将其他对象资料误当作该候选的知识。检索未命中时仍允许模型自主提出知识库外的答案。
- 修复具体名字被误标为 `action=ask` 时无法确认的问题：当指认问句与模型自己的候选名单匹配时，纠正为具体猜测；随后仍执行模型核查与用户确认。普通属性问题保留原意。

## 资料来源

奶龙外观、角色身份及小七等信息核对了[第七印象官方角色介绍](https://www.nailoong.com/ipStar/Nailong/)和[官方网站首页](https://www.nailoong.com/)。参考资料不表示本局秘密答案就是奶龙。

## 检查与测试方法

- 离线测试：405 项通过，8 项真实接口测试默认跳过。
- 本次修改文件 ESLint、TypeScript 类型检查及生产构建通过。仍有既有 TFJS/PDF 大资源块提示。
- 真实接口：经用户授权使用项目测试密钥调用 `https://api.deepseek.com/v1`，模型 `deepseek-flash`，八个目标分别从零开始，每个最多 60 轮。
- 八局采用相同的知识库初始状态，仅预置奶龙资料，不为其他七个目标加入专用资料。猜测模型不接收测试的秘密目标；玩家由另一次模型请求模拟，只有 yes/no/unsure 被交给猜测模型。
- 最终测试让模拟玩家另存一条简短事实依据，便于审查是否迎合问题、误读用途或偷换目标。依据和秘密目标不发送给猜测模型。接受「月球/月亮」等预先声明的同义名称。

## 最终真实测试结果

| 目标       | 最终结果           | 轮数 |
| ---------- | ------------------ | ---- |
| 奶龙       | 猜中               | 7    |
| 微波炉     | 猜中               | 20   |
| 大熊猫     | 猜中               | 10   |
| 皮卡丘     | 猜中               | 12   |
| 孙悟空     | 猜中               | 30   |
| 电风扇     | 猜中               | 54   |
| 月亮       | 未猜中，按上限结束 | 60   |
| 埃菲尔铁塔 | 猜中               | 48   |

最终真实用例共 7 项通过、1 项未通过。八局均没有请求或确认流程错误；未通过的月亮在第 60 轮按规则结算为未猜中。该用例的断言保持失败，没有放宽判定或隐藏结果。

奶龙在三轮知识库接入后的测试中分别于第 5、7、7 轮猜中，说明本次参考资料确实补充了候选召回；三轮配置有调整，不能作为正式重复盲测。电风扇在最终这局用了 54 轮，说明增加上限对该样例有帮助。

月亮最终局没有发生请求错误，但模型围绕生活用品及文学关联持续提问，没有恢复到天体范围。60 轮上限能防止无限对局，不能保证模型的分类和搜索策略正确。

## 已保留的问题证据

首次八目标测试有三个失败样例，暴露了具体答案误标为普通问题，以及模拟玩家误将偶尔能力当作主要用途的问题。修复确认流程后再次测试仍有微波炉、月亮失败，前者有不相关资料干扰候选核查，后者包含模拟玩家错误回答。随后隔离候选资料，并改进模拟玩家的可审查输出。

- 首次报告：`output/guess-live-60-rounds-initial-results.json`，详细记录：`output/guess-60-initial/`。
- 确认流程修复后的报告：`output/guess-live-60-rounds-confirmation-fix-results.json`，详细记录：`output/guess-60-confirmation-fix/`。
- 最终报告：`output/guess-live-60-rounds-results.json`，每个目标的原始问答和模型回复：`output/guess/`。

这些是开发中的少量真实接口样例，包含模型模拟玩家和多次调整，不能当作盲测准确率，也不能保证真人对局每次都猜中或轮数固定。仍需用真人回答检查歧义和稳定性。所有报告均不写入接口密钥。
