## 一、项目概述

### 1.1 背景与目标

市面上的对话类产品大多是「一个对话框打天下」：用户面对空白输入框不知道能问什么。

本项目做一个**随身智囊团**移动端 app：三类场景（找人聊、查自己的资料、算数据趋势）合到一个 App 里，统一记忆层把它们串起来；模型能力通过 OpenAI 兼容接口接入，数据预测在浏览器本地训练，手机打开即用。

| 能力     | 一句话说明                                                             |
| -------- | ---------------------------------------------------------------------- |
| **问人** | 多角色对话平台：**12 个细分领域、81 位内置角色**（先贤、老师、工程师、设计师、医生、律师、厨师……），外加万能对话入口与自建角色 |
| **问知** | 导入自己的资料，基于资料回答并标注出处                                 |
| **问数** | 在手机浏览器里本地训练模型并预测                                       |

### 1.2 技术栈

以前端技术为主体，模型与算法作为其中一层能力：

| 类别         | 选型                                                                 |
| ------------ | -------------------------------------------------------------------- |
| 语言         | TypeScript、JavaScript、HTML5、CSS3            |
| 框架与构建   | Vue 3、Vite 6、pnpm             |
| 状态与路由   | Pinia 3、Vue Router 4（hash 模式）                      |
| 样式与动效   | CSS  |
| 存储         | IndexedDB、Cache Storage、localStorage |

### 1.3 关键实现点

> 状态已与代码逐项核对：✅ 已实现 / ❌ 未实现。

- ✅ 手写 SSE 流式解析与增量渲染；rAF 帧批量提交、Markdown 分片解析
- ✅ 多角色平台：结构化人设（身份 / 语气 / 知识边界 / 禁忌）驱动 system prompt；81 位内置角色覆盖 12 个细分领域，按 7 个展示分组折叠展示并支持关键词搜索；自建角色与「一句话临时人设」持久化在 `kv`，由角色注册表统一解析
- ✅ 手写余弦相似度向量检索（不引入向量数据库），关键词检索兜底
- ✅ TensorFlow.js 在 Web Worker 中本地训练，训练进度可视化
- ✅ 问数按**时间顺序**切分训练/测试集，评估指标在**测试集**上计算（不是样本内拟合），且**归一化只用训练段拟合 min/max** —— 否则缩放器会「见过」测试数据，属数据泄漏；界面标明「测试集指标」并给出训练集内 R² 作过拟合对照
- ✅ 跨会话搜索：IndexedDB **游标逐条扫描**（不把消息全表读进内存）+ 扫描/命中双上限，命中词高亮并一键跳回原会话
- ✅ **猜心玩法（选做，P8）**：把对话约束成「每轮只问一个封闭式问题」的状态机，要求模型返回结构化 JSON，候选集逐轮收敛，最多 20 轮；违规只重问一次、再违规换兜底问题继续
- ✅ 自研**定高虚拟滚动**（`useVirtualList`）并复用于分块浏览与 CSV 预览；CSV 解析是逐字符状态机（引号内逗号/换行、`""` 转义、CRLF、BOM、行列不齐补齐）
- ✅ 移动端与无障碍收口：横竖屏限宽、`visualViewport` 键盘避让、系统字号缩放（字号体系 rem 化）、`prefers-contrast` 高对比度、路由切换焦点复位、左右滑动切换会话

#### D. 猜心（选做）

**玩法**：用户心里想好一个东西（人、动物、物品、电影、学科概念都行）但不说出来，App 每轮只问一个能用"是 / 否 / 不确定"回答的问题，用户答完它接着问，直到把答案猜出来。整个玩法由多轮对话驱动，直接复用"问人"的流式对话与提示词组装，属于在已有能力上加的一层玩法，不新增技术栈，故列为选做。

| 编号  | 需求       | 说明                                                                       | 优先级 |
| ----- | ---------- | -------------------------------------------------------------------------- | ------ |
| FR-G1 | 开局与规则 | 一句话讲清玩法并提示"心里想好一个东西，先别告诉我"；点开始即进入对局        | ★      |
| FR-G2 | 单问约束   | 每轮只输出一个问题且必须封闭式（能拿是 / 否回答）；不得一次问多件事、不得重复提问 | ★      |
| FR-G3 | 逐步收敛   | 每轮根据用户回答更新候选集与置信度，按"先大类后细节"逐层二分缩小范围        | ★      |
| FR-G4 | 猜出与结算 | 置信度够高或达到最大轮数（如 20 轮）时给出答案；显示"第几轮猜中"，猜错可继续 | ★      |
| FR-G5 | 对局记录   | 轮数、用时、猜中 / 未猜中结果存本地，支持"再来一局"与历史对局回看           | ★      |

> 实现要点：走问人的同一套流式通道，但每轮要求模型返回结构化 JSON（`{ question, guess, confidence }`）；解析失败、一次问了多件事或重复提问时按规则重问一次；对局内容**不写入记忆层**，避免用户心里想的答案被当成长期记忆留下来。

### 2.3 非功能需求

| 类别           | 指标                                                             |
| -------------- | ---------------------------------------------------------------- |
| **性能**       | 流式输出不掉帧；PDF 解析、向量计算、模型训练不阻塞主线程          |
| **兼容与离线** | iOS Safari / Android Chrome 可用，移动优先；静态资源缓存后离线可打开，预测能力完全离线；Android 侧用 Capacitor 把同一套代码打包成 App（`.apk`）安装到真机运行，装好后离线打开、离线训练的体验与浏览器内一致（iOS 打包需 Mac 与开发者签名，本次只保浏览器可用） |
| **安全与维护** | Key 只存本地、不写死、不提交仓库；Markdown 经 DOMPurify 过滤；PIN 只存哈希；异常中文提示、骨架屏；TS 严格类型、ESLint 0 问题、无障碍适配 |

### 2.4 数据需求与约束

本地持久化统一走 IndexedDB（`DB_VERSION = 2`）：`sessions` / `messages`（复合索引 `sessionId_createdAt` 支持游标分页）、`memories`、`documents` / `chunks`（含向量）、`kv`（设置、密钥、隐私配置、**自建角色**）。

- **约束 1**：接入 OpenAI 兼容协议厂商；DeepSeek **没有 Embedding 接口**，RAG 必须具备不依赖向量化的可用路径。
- **约束 2**：扫描版 PDF 无文本层需保留"粘贴文本"兜底；Canvas 长图有面积上限，超长内容降采样而非截断。
- **假设**：用户自备 API Key；本地引擎须独立可用。
